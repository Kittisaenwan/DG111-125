# Week 8 — Functions Reference

**Function Reference — `ex02_game_utils.c`**

| Function                                    | ทำหน้าที่                                                 | Returns                      |
| ------------------------------------------- | ------------------------------------------------------------------ | ---------------------------- |
| `int clamp(int value, int min, int max)`  | จำกัดค่า value ให้อยู่ระหว่าง min และ max | ค่าที่ clamp แล้ว  |
| `float lerp(float a, float b, float t)`   | Linear interpolation ระหว่าง a และ b ตาม t            | ค่าที่คำนวณได้ |
| `int randomRange(int min, int max)`       | สุ่มตัวเลขระหว่าง min และ max                  | ค่าสุ่ม               |

## คำถาม Reflection — Exercise 2

### 2.1 `clamp` — Pass by Value

**คำถาม:** ทำไม hp ใน `main()` ถึงยังเป็น 150 ทั้งที่ `value` ใน `clamp()` ถูกเขียนทับเป็น 100 ไปแล้ว?

**คำตอบ: ฟังก์ชัน clamp() รับค่า hp แบบ pass-by-value ทำให้ค่าของ hp ใน main() ถูกคัดลอกไปยังพารามิเตอร์ value ภายใน clamp() นั้น ค่าของ value สามารถถูกเปลี่ยนเป็น 100 ได้ แต่การเปลี่ยนแปลงนี้ไม่มีผลต่อค่า hp ต้นฉบับใน main() ดังนั้น HP จึงยังคงมีค่าเป็น 150 ในขณะที่ safeHP มีค่าเป็น `100**


### 2.2 `lerp` — Local Scope

**คำถาม:** ทำไม `main()` ถึงมองไม่เห็นตัวแปร `result` ทั้งที่มันถูกประกาศไว้ในไฟล์เดียวกัน?

**คำตอบ: ตัวแปร result ถูกประกาศไว้ภายในฟังก์ชัน lerp จึงมีขอบเขตแบบ local และสามารถเข้าถึงได้เฉพาะภายใน lerp() เท่านั้น เมื่อการทำงานกลับมายังฟังก์ชัน main() ตัวแปร result จะไม่สามารถใช้งานได้เนื่องจาก main() มีขอบเขตของตัวเอง นี่คือสาเหตุที่การอ้างถึง  ในขอบเขตของ main() ทำให้เกิดข้อผิดพลาด**

### 2.3 `randomRange` — Pass by Value

**คำถาม:** ทำไม `diceMin` ใน `main()` ถึงยังเป็น 1 ทั้งที่ `min` ใน `randomRange()` ถูกบวกเพิ่มเป็น 101 ไปแล้ว?

**คำตอบ: dicemin ถูกส่งไปยัง randomrange() แบบ pass-by-value ดังนั้นตัวแปร min ภายใน randomrange() จึงเป็นเพียงสำเนาของ dicemin เท่านั้น หากมีการเปลี่ยนแปลงค่า min ในระหว่างการดีบั๊ก จะมีเพียงสำเนาภายในฟังก์ชันเท่านั้นที่เปลี่ยนไป ส่วน dicemin ต้นฉบับใน main() จะยังคงมีค่าเป็น `1` เท่าเดิม**

### 2.4 `percentOf` — Pass by Value

**คำถาม:** ทำไม `score` ใน `main()` ถึงไม่เปลี่ยนเป็น 0 ตาม `current` ทั้งที่ `percentOf()` แก้ `current = 0;` ไปแล้ว?

**คำตอบ: ค่าของ current และ total จะถูกส่งไปยังฟังก์ชัน percentof() แบบ pass-by-value ดังนั้นการเปลี่ยนแปลงค่า current ภายในฟังก์ชันจึงไม่มีผลต่อตัวแปร score ในฟังก์ชัน main() ฟังก์ชันนี้จะแปลง current ให้เป็นชนิด float ก่อนทำการหาร เพื่อให้การคำนวณใช้การหารแบบทศนิยม (floating-point division) แทนการหารแบบจำนวนเต็ม (integer division) ด้วยเหตุนี้ ผลลัพธ์ของ 35 / 100 จึงเท่ากับ 0.35 และเมื่อนำไปคูณกับ 100.0f ก็จะได้ค่าเป็น 35.0**
